# دیدبان | سامانه راهبری بازرسی و کنترل کیفیت گروه سرمایه‌گذاری مسکن

نسخه محلی و تعاملی برای گروه سرمایه‌گذاری مسکن: چرخه **۲۴ گامی**، نقش‌های تفکیک‌شده، دوازده شرکت تابعه، تصمیم مستقل معاونت، پنج شرط بستن پرونده و حلقه‌های یادگیری.

## شروع

**[فایل اصلی سامانه — docs/index.html](docs/index.html)** را دانلود و مستقیم در مرورگر باز کنید؛ یا:

```bash
python3 -m http.server 8000 --bind 0.0.0.0 --directory docs
```

سپس `http://localhost:8000` را باز کنید. سرور فقط برای پیش‌نمایش است؛ خود فایل آفلاین نیز کار می‌کند.

- یک فایل خودکفا با CSS، JavaScript، SVG و فونت وزیرمتن داخلی
- فارسی، RTL، تاریخ جلالی، اعداد فارسی، واکنش‌گرا و قابل چاپ
- داده نمایشی در LocalStorage؛ صفحه ورود دارای پنج کارت مجموعه و حساب‌های آماده است؛ دسترسی‌های معاونت به‌صورت درختی باز می‌شوند
- گذرواژه حساب‌های اولیه: `demo123`؛ حساب معاونت: `deputy`
- از «راهنمای سامانه» می‌توانید نسخه مستقل `didban.html` را **بدون داده خصوصی جلسه** دریافت کنید

> **محدودیت مهم:** این نسخه برای نمایش و اعتبارسنجی فرایند است. کنترل نقش در خواندن، عملیات و خروجی اعمال شده، اما LocalStorage **RLS امنیتی واقعی یا Audit غیرقابل‌دست‌کاری فراهم نمی‌کند**. اطلاعات واقعی، محرمانه یا گذرواژه شخصی وارد نکنید. نسخه تولیدی به سرور، احراز هویت امن و پایگاه داده نیاز دارد.

## قابلیت‌های اصلی

- ایجاد پرونده و چند یافته؛ اجرای چرخه ۲۴ گامی و شاخه‌های بازگشت
- معرفی بازرس توسط مشاور، تأیید مدیر ساخت و معاونت، ساخت حساب توسط ادمین
- پیشنهاد بازدید عادی/ناگهانی، ارجاع به کارشناس رشته، تأیید و صدور خودکار مأموریت
- گزارش میدانی و پیوست، ریسک، علت مستقیم و علت ریشه‌ای مستقل
- نظر سه‌سطحی مشاور و تصمیم مستقل معاونت با ثبت‌کننده/تاریخ جدا
- پاسخ شرکت، پنج چرا، علل سیستمی داخلی، گزارش تحلیلی و اعتراض
- چرخه اقدام اصلاحی، رفع علت ریشه‌ای، راستی‌آزمایی و اثربخشی
- کنترل پنج شرط اجباری بستن؛ مسیر سریع ۲۹ روزه بدون حذف شروط
- درس‌آموخته از یافته بسته، توزیع و بازبینی شش‌ماهه؛ حلقه کنترل پروژه
- داشبورد، نه فیلتر، پنج نمودار تعاملی، CSV/JSON محدود به نقش و چاپ
- ثبت خودکار تغییرات بدون حذف فیزیکی در رابط؛ فعال/غیرفعال‌سازی شرکت‌ها

**[راهنمای دامنه، محدودیت‌ها، حساب‌ها و معماری](docs/IMPLEMENTATION.md)**

ساختار ورود از کارت **«معاونت فناوری و مدیریت ساخت گروه»** باز می‌شود؛ مدیران زیر آن و کارشناسان زیر مدیر مربوط هستند. پنج کارشناس رشته زیر مدیر ساخت حفظ شده‌اند و برای طرح و توسعه، کنترل پروژه و قراردادها نیز حساب کارشناس زیرمجموعه اضافه شده است. عنوان کارت «مدیریت و فنی» به **«ادمین ساختار»** تغییر کرده است. مدیرعامل خارج سامانه است. ثبت مأموریت پس از تأیید مدیر ساخت خودکار انجام می‌شود تا ادمین صرفاً به کاربران دسترسی داشته باشد.

## صفحه ورود و مدیران

صفحه ورود بر اساس تصویر مرجع با پنل آبی معماری در سمت چپ، پنج کارت تصویری در سمت راست و فرم مستقل شرکت تابعه بازطراحی شده است. تصاویر نمادین و تعبیه‌شده‌اند و به اینترنت نیاز ندارند. عنوان عمومی سامانه «گروه سرمایه‌گذاری مسکن» است.

| مسئولیت | نام |
|---|---|
| مدیر ساخت | مهندس مهرنوش |
| مدیر طرح و توسعه | خانم مهندس یگانه |
| مدیر دفتر مدیریت پروژه | مهندس گلبو |
| مدیر امور قراردادها | خانم مهندس رنجبر زاده |

**ادمین بازرسان مشاور** زیرمجموعه شرکت مشاور است؛ هم از درخت مشاور و هم از کارت میان‌بر خودش قابل انتخاب است. کارت ادمین ساختار فقط شامل مدیریت سامانه و ادمین زیرساخت است. حساب‌ها و گذرواژه‌ها عوض نشده‌اند؛ نام‌های جدید برای داده‌های ذخیره‌شده قبلی نیز اعمال می‌شوند.

## ارجاع کار در ساختار جدید

معاونت کار را به مدیر ارجاع می‌دهد؛ مدیر در بخش «ارجاع کار و کارشناسان»، کارشناس فعال زیرمجموعه خود را انتخاب می‌کند. پاسخ کارشناس به مدیر برمی‌گردد و مدیر پس از دریافت پاسخ‌های باز، جمع‌بندی مستقل خود را به معاونت ارائه می‌کند. کارشناس کنترل پروژه یا قراردادها به محتوای کامل پرونده دسترسی نمی‌گیرد.

حساب‌های نمونه جدید: `expert-development`، `expert-pmo` و `expert-contracts`؛ گذرواژه اولیه `demo123`. ارتقای ساختار، داده و گذرواژه حساب‌های قبلی را حفظ می‌کند.

## گزارش رشته‌ای و نمونه آماده ارائه

در بخش **«گزارش‌های رشته‌ای»** برای مأموریت‌های منطبق سازه، معماری، برق و مکانیک گزارش مستقل وجود دارد؛ مشخصات بازرس، شرکت، پروژه، شناسه مأموریت و پیشرفت همان پروژه همراه گزارش نگهداری می‌شود. مأموریت جدید گزارش جدید می‌گیرد و اطلاعات گزارش قبلی کپی نمی‌شود.

با حساب مشاور `consultant` و گذرواژه اولیه `demo123`، وارد **«پروژه‌های خرداد ۱۴۰۵»** شوید. «نمونه چهار رشته» برای یک پروژه فعال، چهار پرونده، مأموریت و گزارش عملیاتی مستقل می‌سازد. در صفحه گزارش‌ها نیز دکمه **«نمونه از پروژه‌های خرداد ۱۴۰۵»** وجود دارد. بازرس مربوط می‌تواند نمونه را ویرایش و ارائه کند؛ شرکت فقط نسخه ارائه‌شده خودش را می‌بیند. چاپ و JSON هر گزارش موجود است.

### ورود متن چهار منبع — نسخه ۳

اکنون اطلاعات پیام جدید کاربر ذخیره و وارد شده است؛ **اصل PDFها مستقلاً بررسی نشده‌اند**. فایل‌های `docs/sources/` متن بندها با شماره‌گذاری قابل بازسازی، جدول جزئیات، پیوست نقاط و ثبت ساختاریافته دستورالعمل/راهنمای گزارش را نگه می‌دارند.

- **۶۹ پروژه:** شرکت، نام، وضعیت، نوع، دو مساحت، درصد واقعی تجمعی و تاریخ‌ها وارد شده‌اند. دو مساحت برای ۶۸ ردیف تفکیک شده‌اند؛ عبارت `۹,۰۶۷,۹۲۱` گلشهر تفکیک نشده است. علامت‌های `-` نامشخص می‌مانند. ترتیب مساحت‌ها و تاریخ یکسان اقدام ملی ۲ زین بدون اصلاح حفظ شده‌اند.
- **۵۲۹ رکورد چک‌لیست:** ۴۹۲ ریزبند کامل، ۶ عبارت ناقص، ۳۰ سرفصل بدون ریزمتن و یک بخش ارائه‌نشده (۴-۳). متن ریزبندها دیگر با عنوان عمومی جایگزین نیست؛ کتابخانه با کد فارسی/لاتین، متن و رشته جست‌وجو و صفحه‌بندی دارد.
- شماره‌های `5-6-4-1…8` با والد اعلامی `5-6-3` حفظ شده‌اند. متن بریده قراردادها، جزئیات ناموجود سقف کاذب/مکانیک/بخش‌هایی از برق و آسانسور و ده بند ناموجود محرمانگی ساخته نشده‌اند.
- **۳۶ فعالیت بازرسی اجباری:** درجه و عضویت گروه‌های ۱ تا ۴ ثبت شده است. دو پیوست «ت» برای ایمنی و مدیریت کیفیت با شناسه داخلی جدا حفظ شده‌اند.
- **گزارش عملیاتی نسخه ۳:** کد و متن ریزبندهای مرتبط با رشته و مرحله پیشنهادی، ارزیابی مستقل، علت‌ها و اقدامات؛ برای قسمت فاقد جزئیات، برچسب «فقط سرفصل» روشن است. یافته، امتیاز، بازدید و گروه نمونه همچنان ساختگی‌اند.
- جدول برنامه نقاط اجباری همان رشته، تعداد برنامه/بازدید، واحد و مکان، دلیل و برنامه بازدید مجدد و شواهد دارد. فعالیت اجباری با تعداد نقاط واقعی یکی نیست؛ مقدار نامعلوم خالی و پوشش کل تا تکمیل شمارش نامعلوم است. ایمنی و مدیریت کیفیت مشترک تیم جدا نمایش داده می‌شوند. پیوست اختصاصی نقاط سازه در پیام نبود؛ خالی‌بودن جدول به معنی نبود الزام نیست.
- پیشرفت برنامه‌ای، تأییدشده و انحراف همچنان خالی‌اند، چون در جدول منبع نیامده‌اند. درصد کل اثبات اتمام رشته نیست. حداقل پوشش/بازدید گروه با پوشش تحقق‌یافته اشتباه گرفته نمی‌شود.

گزارش‌های عمومی نسخه ۱ و سرفصلی نسخه ۲ با محتوا و منشأ قبلی حفظ می‌شوند؛ نمونه جدید نسخه ۳، مستقل است. برای پروژه‌ای که قبلاً نمونه نسخه ۲ ساخته‌اید نیز می‌توانید نمونه تازه نسخه ۳ بسازید. ارائه، تاریخچه و قفل نسخه را ثبت می‌کند و نه تأیید مشاور، تصمیم معاونت یا پیشروی خودکار چرخه ۲۴ گامی.

**محدودیت اجرایی:** ارسال فرم تکمیل‌شده کاربر برای بررسی کامل‌بودن توسط مشاور فعال است؛ این ارسال، گواهی رسمی کیفیت، تصویب برنامه اجرایی یا راستی‌آزمایی بیرونی مدارک نیست. متن برنامه بازدید مجدد، صدور مأموریت نیست. فرم‌های مستقل کامل R-M/R-A/R-N، گردش کامل نامه توقف و راستی‌آزمایی بیرونی مدارک هنوز تکمیل نشده‌اند. هشدار گزارش عمده/بحرانی به معاونت فرستاده می‌شود؛ توقف کتبی خودکار صادر نمی‌شود.

## تکمیل فرم به تفکیک بازرس، شرکت، پروژه و رشته

این فرم دیجیتال بر ساختار R-O خوانای قبلی استوار است. پیوست جدید **«فرم گزارش خام.pdf» در محیط قابل خواندن نبود**؛ تطبیق صفحه‌به‌صفحه آن انجام نشده و `rawTemplateVerified:false` است. برای انطباق دقیق، تصویر یا فایل قابل‌خواندن صفحات لازم است.

۱. مشاور پرونده و مأموریت را برای بازرس واجد شرایط همان رشته ایجاد می‌کند؛ همه پرونده‌های تازه، حتی پروژه‌های خارج از جدول ۶۹ پروژه، قالب جدید می‌گیرند. شرکت، پروژه، مأموریت، بازرس و رشته فرم ثابت‌اند. پیشرفت و مرحله نامعلوم حدس زده نمی‌شوند.
۲. بازرس در «گزارش‌های رشته‌ای» از فیلترهای شرکت، پروژه، بازرس و رشته استفاده می‌کند و بندهای چک‌لیست را تأیید می‌کند؛ مرحله از درصد پیشرفت حدس زده نمی‌شود. بندهای خارج از دامنه با دلیل و سابقه نگهداری می‌شوند؛ انتخاب بند به معنی تأیید انطباق نیست.
۳. برای هر بند تنها یک نتیجه تیک می‌خورد: انطباق، عدم‌انطباق جزئی/عمده، بحرانی، فرصت بهبود، بازدیدنشده یا نامرتبط. تیک بررسی ردیف، محل، مشاهده، شاهد، اندازه‌گیری/کنترل کیفی و امتیازهای مستقل ثبت می‌شوند. بازدیدنشده/نامرتبط امتیاز ندارند و دلیل لازم دارند؛ بازدیدنشده در فرم غیرنمایشی برنامه مجدد هم می‌خواهد.
۴. پیش‌نویس ناقص ذخیره می‌شود. ارسال غیرنمایشی در مرحله مناسب بازدید، پس از ارجاع نقطه اجباری توسط مشاور، تأیید دامنه/ردیف‌ها، تاریخ و ساعت معتبر، کنترل کیفی، پیوست تصویر/PDF و تصدیق بازرس مجاز است. نسخه ارسال‌شده قفل می‌شود.
۵. مشاور مسئول، کامل‌بودن فرم را تأیید یا اصلاح درخواست می‌کند. اصلاح در نسخه مستقل با حفظ نسخه قبلی انجام می‌شود. این رسید جای نظر کارشناسی گام ۱۲ نیست.
۶. پس از رسید قبول، بازرس گزارش را صریحاً به واقعیت‌ها و شواهد گام ۷، یا مرجع بازدید مجدد گام ۲۰ متصل می‌کند. اتصال خودکار گام را جلو نمی‌برد. نظر مشاور، تصمیم معاونت، عدم‌انطباق، ریسک، علت‌ها و تأیید رفع همچنان مستقل‌اند.

**حدود اجرا:** اتصال به یافته موجود است؛ تبدیل خودکار هر ردیف عدم‌انطباق به یافته مستقل پیاده نشده است. تعیین یافته‌های مستقل و ادامه چرخه باید جدا انجام شود. ذخیره مرورگر جای پایگاه داده امن، امضای معتبر یا ممیزی تغییرناپذیر سرور را نمی‌گیرد. نمونه‌های پرشده صریحاً ساختگی‌اند.

### رفع مسیر تکمیل فرم بازرس در ارجاع‌های موجود

- گزارش‌های قدیمی حساب‌های اولیه از قبل «ارسال‌شده» و قفل بودند. اکنون در صفحه نخست بازرس، کارتابل، پرونده و برنامه‌های بازدید، دکمه **«تکمیل چک‌لیست و گزارش تحلیلی»** برای ارجاع خود او وجود دارد. هیچ نیاز به پاک‌کردن LocalStorage یا حذف سوابق نیست.
- در مرحله بازدید، فرم خالی مستقل همان مأموریت آماده می‌شود؛ گزارش قدیمی دست‌نخورده می‌ماند. پس از مرحله گزارش اولیه، فرم **تکمیلی** آماده می‌شود و پس از بررسی مشاور، فقط به سوابق پیوست می‌شود؛ واقعیت‌ها، علل تأییدشده، نظر و تصمیم قبلی را بازنویسی نمی‌کند.
- تحلیل بازرس، علت مستقیم، عامل مشارکت‌کننده، علت ریشه‌ای پیشنهادی، شواهد علت، فرایند ناموفق و مسئولیت، فیلدهای چندخطی آشکار دارند. برای ارسال NC غیرنمایشی، تحلیل، علت مستقیم، پیشنهاد علت ریشه‌ای و مبنای آن لازم‌اند؛ اگر علت احراز نشده، نامعلوم‌بودن و بررسی لازم ثبت می‌شود، نه علت ساختگی.
- ذخیره پیش‌نویس با محل و جمع‌بندی خالی در خود مرورگر نیز مجاز است. برای ارسال نهایی، الزامات دامنه، بازدید، مستندات و بررسی همچنان برقرارند.
- مسیر آزمایش سریع: حساب `inspector` با رمز `demo123` ← «ارجاع‌های من» ← مأموریت «افق» ← «تکمیل چک‌لیست و گزارش تحلیلی». حساب‌های `inspector3`، `inspector4` و `inspector5` نیز فرم‌های ارجاع خود را برای معماری، برق و مکانیک دارند. داده‌های اولیه، نمونه‌اند.

### انتخاب فقط از چک‌لیست و ارجاع نقطه توسط مشاور — رفتار جاری

این بخش جایگزین انتخاب حدسی بندها از درصد پیشرفت در فرم‌های تازه غیرنمایشی است. متن فرم خام جدید هنوز قابل خواندن نبوده؛ **انطباق ستون‌ها و صفحه‌آرایی با آن تأیید نشده است**. عناوین بندها فقط از چک‌لیست خوانای قبلی کاربر می‌آیند؛ بند، ریزمتن یا عنوان جدید ساخته نمی‌شود.

**مسیر مشاور:** «برنامه‌های بازدید» ← برنامه همان بازرس/پروژه ← «ارجاع نقطه اجباری از چک‌لیست» ← انتخاب از کشویی رشته و ثبت محل دقیق. هر نقطه شناسه مستقل دارد؛ همان بند در دو محل، دو نقطه مستقل است. برای چند نقطه، این کار تکرار می‌شود. تأیید و صدور مأموریت تازه چهار رشته، بدون ارجاع نقطه ممکن نیست. مشاور دیگر و بازرس اجازه ساخت نقطه اجباری ندارند.

**مسیر بازرس:** «تکمیل چک‌لیست و گزارش تحلیلی» ← نقاط اجباری ارجاع‌شده نمایش داده می‌شوند ← کشویی «فراخوانی بند دیگر از چک‌لیست» برای بندهای اضافی ← گزارش، تحلیل و «عکس یا مستند همین بند». افزودن بند، نوشته‌ها و فایل‌های جاری را اول به شکل پیش‌نویس ذخیره می‌کند. تصویر در همان بند قابل دیدن و دریافت است و ارتباط بند/عکس در خروجی و بازخوانی حفظ می‌شود.

- کشویی فقط بندهای قابل انتخاب رشته و بندهای مشترک منبع را دارد. بند ناقص یا ناموجود قابل انتخاب نیست؛ سرفصل فاقد ریزمتن با همان محدودیت نمایش داده می‌شود.
- نقطه اجباری قابل حذف یا تبدیل به «نامرتبط» توسط بازرس نیست. عدم امکان بازدید با «بازدیدنشده»، دلیل و برنامه مجدد گزارش می‌شود؛ انجام بازدید جعل نمی‌شود. بندهای اضافی بازرس با حفظ سابقه قابل کنارگذاشتن‌اند.
- فرم تازه بدون ارجاع یا انتخاب کاربر، ردیف حدسی ندارد؛ نوع اقدام هم پیش‌فرض ساختگی ندارد. پیش‌نویس قبل از ارجاع قابل تکمیل است، ولی ارسال غیرنمایشی منتظر نقطه اجباری مشاور می‌ماند.
- ماتریس ۳۶ فعالیت اجباری **منبع** با **نقطه مکانی ارجاع مشاور** یکی نیست. نمایش جدول منبع به معنی ارجاع، تعیین تعداد واقعی یا تأیید بازدید نیست.
- عکس PNG/JPEG یا PDF، حداکثر ۵۰۰ کیلوبایت برای هر فایل و چهار فایل در هر ذخیره؛ فایل‌های بیشتر را در ذخیره بعدی اضافه کنید. سقف فضای LocalStorage مرورگر برقرار است و فایل نامعتبر/ذخیره ناموفق تراکنش را برمی‌گرداند.
- ارجاع جدید پس از ارسال فرم همان مأموریت ممنوع است؛ مأموریت تازه لازم است تا دامنه نسخه ارسال‌شده تغییر نکند. عکس و تحلیل جدید نیز نسخه ارسال‌شده را باز نمی‌کند.

## حذف تصاویر نمونه

تمام عکس‌های اینترنتی نمونه، گالری، بزرگ‌نمایی و نمایش آن‌ها در گزارش و چاپ حذف شده‌اند. فایل HTML دیگر باینری یا پیوند منابع آن تصاویر را ندارد. این تغییر داده‌های پرونده‌ها، درس‌آموخته‌ها یا مدارک شخصی کاربر را حذف نمی‌کند؛ امکان بارگذاری مدارک بازرس باقی است. طراحی صفحه ورود تغییری نکرده است.

## بانک درس‌آموخته‌های مبتنی بر علل ریشه‌ای

بانک اولیه اکنون **۱۰ مورد** دارد: یک درس متصل به علت ریشه‌ای یافته بسته موجود و ۹ سناریوی آموزشی با برچسب روشن. برای پرکردن بانک، هیچ پرونده جدیدی بسته‌شده فرض نمی‌شود و به سناریوهای آموزشی، پروژه یا فراوانی واقعی نسبت داده نمی‌شود.

هر کارت علت ریشه‌ای عمومی، درس حاصل، اقدام پیشگیرانه، معیار پیشنهادی اثربخشی و موعد بازبینی شش‌ماهه را جدا نشان می‌دهد. موضوع نمونه‌ها: کنترل پیش از اجرا، صلاحیت و آموزش، هماهنگی نقشه‌ها، کنترل نسخه مدارک، پذیرش مصالح، مسئولیت پیمانکاران، اعتبار اندازه‌گیری، نگهداری، مدیریت تغییر و ایمنی.

- مدیر طرح و توسعه در «درس‌آموخته از علت مرجع»، یافته بسته را انتخاب می‌کند؛ متن علت ریشه‌ای واقعی منبع پیش از ثبت نمایش داده می‌شود و snapshot آن داخل درس ذخیره می‌شود. علت مستقیم جایگزین ریشه‌ای نمی‌شود.
- همه منابع انتخاب‌شده باید معتبر باشند؛ انتخاب ترکیبی منبع معتبر با یافته باز، ناموجود یا بدون علت پذیرفته نیست. الگوی عمومی برای انتشار، جدا از متن دقیق منابع نوشته می‌شود تا هویت و اطلاعات اختصاصی پروژه به سایر شرکت‌ها نرود.
- شناسه‌ها و متن دقیق منابع فقط برای طرح و توسعه و معاونت قابل مشاهده‌اند. نقش‌های دیگر تنها محتوای عمومی توزیع‌شده را می‌گیرند. ادمین‌ها بانک را دریافت نمی‌کنند.
- با تغییر علت ریشه‌ای مرجع، snapshot درس قدیمی دست‌نخورده می‌ماند و توزیع پیش‌نویس ناسازگار مسدود است. درس تازه باید بر اساس علت به‌روز تهیه شود.
- ارتقای مرورگر افزایشی و یک‌باره است: بانک کمتر از ۱۰ مورد تا ۱۰ پر می‌شود؛ درس‌های کاربر حذف یا بازنویسی نمی‌شوند. اگر از قبل ۱۰ یا بیشتر داشته‌اید، تعداد کم نمی‌شود. ۱۰ سقف ثبت درس‌های آینده نیست.

## آزمون‌ها

```bash
# بدون وابستگی — آزمون قواعد، چرخه و دسترسی
node --test tests/domain.test.cjs

# وابستگی‌های توسعه برای آزمون مرورگر، نه برای اجرای سامانه
npm ci --prefix tests
cd tests
npx playwright install chromium
npm run test:browser
node source.browser.mjs
node report-form.browser.mjs
node inspector-entry.browser.mjs
node checklist-referral.browser.mjs
node no-demo-photos.browser.mjs
node root-lessons.browser.mjs
```
